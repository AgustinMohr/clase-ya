# Security Policy

## Supported Versions

Security updates are currently provided for the latest version of the `main` branch.

## Reporting a Vulnerability

If you discover a security vulnerability in ClaseYa, please report it privately rather than opening a public GitHub issue.

You can report vulnerabilities through GitHub's private vulnerability reporting:

https://github.com/AgustinMohr/clase-ya/security/advisories/new

Please include, when possible:

* A clear description of the vulnerability.
* The steps required to reproduce it.
* The potential impact.
* Any relevant logs, screenshots, or proof of concept.
* A suggested mitigation, if known.

## Responsible Disclosure

Please do not publicly disclose a security vulnerability until it has been reviewed and, when appropriate, fixed.

Security reports will be reviewed on a best-effort basis.

## Scope

Security reports are particularly relevant for issues involving:

* Authentication and authorization.
* Exposure of personal or private information.
* Injection vulnerabilities.
* Session or JWT handling.
* Access control.
* File uploads.
* API security.
* Dependency vulnerabilities.
* Secrets or credentials accidentally exposed in the repository.
